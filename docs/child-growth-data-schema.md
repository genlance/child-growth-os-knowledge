# child-growth-os 孩子成长数据表设计说明

本说明用于本地 Excel、飞书多维表格和 agent 数据读写。表名面向 0-18 岁长期使用，统一使用“孩子”，不再使用“宝宝档案”作为核心表名。

本地轻量版中，`ChildGrowthOS.xlsx` 是家长可直接查看的主表格，必须与 agent 的 `data/*.jsonl` 或兼容 JSON 同步更新。JSON/JSONL 不能替代 Excel，只能作为 agent 内部数据层。

## 命名原则

- `孩子档案` 是根表，记录孩子长期身份信息。
- `照片资产库` 是所有照片、视频、单据截图的唯一入口。
- 其他事件表通过关联字段连接 `照片资产库`，不要把照片散落在各表里。
- 飞书已有旧表时，优先沿用并迁移字段，不要重复新建。
- 如果旧表叫 `宝宝档案`、`宝宝当前状态`，应优先建议重命名为 `孩子档案`、`孩子当前状态`，原有记录和字段必须保留。

## 子表总览

| 子表 | 作用 | 什么时候写入 |
| --- | --- | --- |
| 孩子档案 | 孩子的基础信息和长期画像，是所有记录的根 | 首次安装、生日/过敏/家庭成员等稳定信息变化时 |
| 每日成长日记 | 把一天里的零散输入整理成故事卡 | 每天有文字、照片或晚上 21 点复盘时 |
| 照片资产库 | 所有照片、视频、医生单据、报告截图的统一资产表 | 用户发照片/文件，或批量导入旧照片时 |
| 成长时间轴 | 重要第一次、里程碑、家庭大事 | 第一次、明显进步、旅行、入园、入学等节点 |
| 喂养记录 | 奶量、辅食、食物探索、过敏反应 | 喂奶、辅食、第一次吃某食物、过敏观察 |
| 睡眠记录 | 入睡、夜醒、小睡、睡眠质量 | 用户记录睡眠或夜醒变化时 |
| 尿片记录 | 小便、大便、尿布疹、排便状态 | 0-1 岁高频记录，或消化/脱水/便秘观察时 |
| 健康档案 | 发热、咳嗽、疫苗、体检、医生单据、外伤 | 看医生、体检、打疫苗、用药记录、上传报告时 |
| 身体成长曲线 | 身高、体重、头围和体检结果 | 体检、家中测量、成长曲线截图 |
| 育儿知识映射 | 把育儿知识绑定到这个孩子的真实事件 | 记录触发某个育儿主题、建议和反馈时 |
| 育儿实验闭环 | 问题、假设、行动、观察、结果 | 睡眠调整、喂养策略、行为引导等需要复盘时 |
| 孩子当前状态 | AI 维护的近期状态摘要 | 每日/每周更新，供后续回答和推送参考 |
| 家庭书信 | 父母写给孩子的话、亲子互动和未来信 | 生日、重要节点、父母想留下话时 |
| 已安装子技能 | 记录技能安装、版本和更新状态 | 安装/更新子技能时 |
| 同步日志 | 本地、飞书、导入、导出之间的同步结果 | 每次同步、迁移、导入、导出后 |
| 导入确认清单 | 旧资料扫描后的待确认项目 | 批量导入旧照片、旧日记、旧 App 数据前 |

## 字段设计

### 孩子档案

用途：孩子的基础身份、家庭背景和长期画像。

建议字段：

- 孩子称呼
- 出生日期
- 性别
- 出生体重
- 出生身高
- 出生医院
- 血型
- 过敏史
- 家庭成员
- 父母留言
- AI 孩子画像
- 当前阶段摘要
- 关联每日成长日记
- 关联照片资产

旧字段兼容：

- `宝宝昵称` 可迁移为 `孩子称呼`
- `宝宝档案` 表可重命名为 `孩子档案`

### 每日成长日记

用途：每天一张故事卡，不是简单流水账。

建议字段：

- 日期
- 孩子年龄
- AI 标题
- 封面照片
- 家长原始输入
- AI 成长故事
- 关键词
- 情绪标签
- 重要程度
- 关联照片
- 关联成长时间轴
- 关联喂养记录
- 关联睡眠记录
- 关联健康档案
- 晚间复盘状态
- 晚间补充
- 补充时间
- 记录人

### 照片资产库

用途：所有照片、视频、医生单据、报告截图的唯一资产库。

建议字段：

- 文件大小
- 修改时间
- 短校验值
- 命名置信度
- 状态：已确认 / 待确认 / 疑似错配 / 已修复
- 来源渠道
- 来源消息 ID
- 上传状态
- 拍摄日期
- 孩子年龄
- 媒体类型
- 事件类型
- 人物
- 地点
- AI 描述
- 标签
- 情绪
- 重要程度
- 关联每日成长日记
- 关联成长时间轴
- 关联喂养记录
- 关联睡眠记录
- 关联尿片记录
- 关联健康档案
- 关联身体成长曲线
- 关联家庭书信
- 导出文件夹
- 导出排序

硬规则：

- 飞书中 `原始附件` 必须是附件字段。
- 不允许只把照片命名为一个文件名就算保存完成。
- 批量照片命名必须先建立逐文件媒体清单，不能把 AI 生成的一组描述按列表顺序套回照片文件。
- 如果命名置信度不足，使用中性文件名并标记为 `待确认`。
- 健康档案里的医生单据、疫苗本、检查报告也进入照片资产库。

## 飞书旧表识别与升级规则

agent 在飞书模式或双备份模式下，必须先检查用户是否已经有旧多维表格。

用户可能给出：

- 飞书多维表格链接
- app_token
- base 名称
- 截图中的已有表结构

执行顺序：

1. 先读取已有 base 的表列表。
2. 使用表名匹配旧表和新表。
3. 对旧表进行字段检查和补字段。
4. 能重命名就重命名，不重复建表。
5. 只有缺少某个子表且用户确认后，才新建该子表。
6. 所有升级前都先生成字段差异说明。

旧表名兼容：

| 旧表名 | 新表名 |
| --- | --- |
| 宝宝档案 | 孩子档案 |
| 宝宝当前状态 | 孩子当前状态 |

字段升级规则：

- 只追加字段，不删除已有字段。
- 不清空已有记录。
- 不重建已有表。
- 不改变已有附件字段的数据。
- 不覆盖用户手动添加的字段。
- 字段类型冲突时，保留原字段，新建兼容字段并标注说明。

升级前给用户的说明：

```text
我检测到你已经有一套飞书育儿表格。
我会优先沿用旧表，不会新建一套空表覆盖它。

本次只会做：
- 把“宝宝档案”建议重命名为“孩子档案”
- 补充缺失字段
- 检查照片资产库是否有真实附件字段
- 建立照片资产库和各事件表的关联字段

我会先给你字段差异清单，确认后再执行。
```
