# ChildGrowthOS 旧资料导入协议

很多家庭不会从孩子出生第一天就开始使用 child-growth-os。旧资料导入能力的目标，是把过去散落在手机相册、微信、旧日记、其他育儿 App、Excel 和飞书里的资料，安全地迁移成可回看、可分析、可生成时间轴的孩子成长档案。

核心原则：

```text
先扫描，生成待确认清单，不直接导入。
```

agent 在用户确认前，不得把旧资料写入正式 `data/*.jsonl`、`ChildGrowthOS.xlsx` 或飞书正式表。

## 导入总流程

所有导入来源都走同一套五步流程：

1. **选择来源**：用户提供旧照片文件夹、微信导出、日记文档、Excel/CSV、飞书导出、手机相册整理包或其他育儿 App 导出。
2. **只读扫描**：读取文件名、目录、EXIF、文本、表头、附件关系和可识别内容，不修改原文件。
3. **生成待确认清单**：输出到 `imports/staging/` 和 `imports/reports/`；旧照片/相册导入时优先生成本地网页，让用户一边看照片一边补故事。
4. **用户确认**：用户可以批量确认、逐条修改、跳过、合并重复项或指定目标表。
5. **正式导入**：确认后才写入照片资产库、每日成长日记、成长时间轴、健康档案、喂养记录、睡眠记录等正式数据表。

## 标准导入目录

```text
ChildGrowthOS/
├── imports/
│   ├── raw/
│   │   └── {import-task-id}/
│   ├── staging/
│   │   ├── {import-task-id}.jsonl
│   │   └── {import-task-id}-review.csv
│   ├── reports/
│   │   ├── {import-task-id}-summary.md
│   │   └── {import-task-id}-issues.md
│   └── review/
│       └── {import-task-id}/
│           ├── index.html
│           ├── assets/
│           └── reviewed-items.json
└── data/
    └── import-tasks.jsonl
```

`imports/raw/` 保存原始资料副本或来源路径记录。  
`imports/staging/` 保存机器可读待确认清单。  
`imports/reports/` 保存给用户看的摘要和问题清单。
`imports/review/` 保存本地照片故事填写页。

## 用户可编辑字段

待确认清单必须给用户留下可改字段，不要把 AI 判断当成最终事实。

建议用户可改字段：

- 是否导入：导入 / 跳过 / 稍后确认
- 日期
- 时间
- 标题
- 事件说明
- 人物
- 地点
- 标签
- 目标表
- 是否重要节点
- 是否第一次
- 是否健康/医疗资料
- 关联已有记录
- 家长补充文字
- AI 描述是否采用

## 本地照片故事填写页

旧照片文件夹、手机相册整理包、宝宝相册 App 导出的照片包，默认不要只给 CSV 或 JSON。普通家长最容易接受的是本地网页：

```text
imports/review/{import_task_id}/index.html
```

页面目的：

- 左边看照片或视频缩略图。
- 右边填写这张照片对应的故事。
- 日期、孩子年龄、文件名、相册名、AI 识别内容由 agent 预填。
- 家长只需要补“故事 / 标签 / 情绪 / 是否导入”等记忆信息。
- 用户确认后再正式导入育儿档案。

推荐页面布局：

```text
顶部：导入任务标题、已填写数量、保存草稿、导出结果
左侧：照片预览、原文件名、asset_id、日期来源、相册/文件夹线索
右侧：可编辑表单
底部：上一张、下一张、批量复制字段、跳过、标记稍后确认
```

右侧表单字段：

- 日期
- 孩子年龄
- 事件类型：日常 / 第一次 / 喂养 / 睡眠 / 健康 / 体检 / 旅行 / 生日 / 入园入学 / 家庭书信 / 其他
- 人物
- 地点
- 故事描述
- 标签
- 情绪
- 重要等级：普通 / 值得保存 / 重要 / 非常重要
- 是否第一次
- 目标表：照片资产库 / 每日成长日记 / 成长时间轴 / 健康档案 / 喂养记录 / 睡眠记录 / 家庭书信
- 是否导入：导入 / 跳过 / 稍后确认
- 家长备注

页面行为规则：

- 自动保存到浏览器本地缓存，避免用户填写一半丢失。
- 支持导出 `reviewed-items.json`。
- 可选导出 `reviewed-items.csv`，方便用户用 Excel 检查。
- 不直接写正式档案。
- 不上传用户照片到外部服务。
- 图片使用相对路径，整个 `ChildGrowthOS` 文件夹复制后仍可打开。
- 如果浏览器安全限制导致图片无法显示，agent 应启动本地静态服务或生成可打开的相对路径版本。

正式导入入口：

用户完成填写后，可以说：

```text
我已经填完相册故事页，请按 reviewed-items.json 正式导入。
```

agent 应读取 `imports/review/{import_task_id}/reviewed-items.json`，检查必填项和重复项，生成导入摘要，再请求用户最后确认。用户确认后，才写入：

- `照片资产库`
- `每日成长日记`
- `成长时间轴`
- `健康档案`
- `喂养记录`
- `睡眠记录`
- `ChildGrowthOS.xlsx`
- `data/*.jsonl`

用户确认后，正式导入时应同时保留：

- `ai_description`
- `user_note`
- `original_source`
- `confidence`
- `reviewed_by_user`

## 标准导入方式

### 1. 旧照片文件夹

适用：用户电脑、移动硬盘、网盘下载包、相机备份里的一堆照片。

扫描内容：

- 文件路径
- 文件名
- 文件大小
- 图片尺寸
- 文件类型
- EXIF 拍摄时间
- EXIF 设备信息
- GPS 信息，如有
- 文件修改时间
- 文件夹年月线索
- 图片内容理解
- 是否重复照片

日期判断优先级：

1. EXIF `DateTimeOriginal`
2. EXIF `CreateDate`
3. 文件名里的日期
4. 上级文件夹年月
5. 文件修改时间
6. 用户提供的默认日期或日期范围

AI 内容识别应产出：

- 画面描述
- 可能事件类型
- 人物
- 场景
- 情绪
- 是否像重要节点
- 是否像医疗单据/报告
- 是否适合作为封面照片

待确认清单必须包含：

- 原图缩略图或相对路径
- AI 建议标题
- AI 描述
- 推测日期和日期来源
- 建议标签
- 建议目标表
- 需要用户补充的空字段

同时必须生成本地照片故事填写页，除非用户明确只要 CSV/Excel 清单。

网页里日期和孩子年龄可以预填，但故事描述、地点、标签、是否第一次、是否导入必须允许用户修改。不要把 AI 的照片描述当成家长记忆。

确认后写入：

- `照片资产库`
- `每日成长日记`，如果用户确认这是一个有故事的事件
- `成长时间轴`，如果是第一次、生日、入园、旅行、重要家庭节点
- `健康档案`，如果是医生单据、检查报告、疫苗记录或伤口照片

### 2. 微信聊天记录导出

适用：用户从微信导出和孩子相关的聊天文本、图片、视频、文件。

扫描内容：

- 消息时间
- 发送人
- 文本内容
- 图片/视频/文件路径
- 图片与前后文关系
- 语音转文字结果，如可用
- 表情和短句里的情绪线索

处理规则：

- 同一时间段内的文字和图片应尝试合并为一个事件。
- 图片不能只保存路径，正式导入时必须进入 `照片资产库`。
- 医生单据、疫苗本、检查报告应归入健康相关事件。
- 家长原话必须保留到 `每日成长日记.家长原始输入`。

确认后写入：

- `每日成长日记`
- `照片资产库`
- `成长时间轴`
- `健康档案`
- `家庭书信`，如果文本明显是给孩子的留言

### 3. 以前手写/Word/Markdown/TXT 日记

适用：家长以前写在文档、备忘录、公众号草稿、Markdown 文件、Word 文件里的成长日记。

扫描内容：

- 文档标题
- 段落日期
- 文本中的年龄、事件、地点、人物
- 是否有图片引用
- 是否有“第一次”“生病”“体检”“生日”等关键节点

处理规则：

- 不能把整篇长文直接塞进一条记录。
- 应按日期、标题或事件切分成多条候选成长日记。
- 原文保留，AI 故事另写。
- 如果无法确定日期，必须放入待确认清单。

确认后写入：

- `每日成长日记`
- `成长时间轴`
- `家庭书信`
- `育儿知识映射`，如果文中包含家长采取的育儿方法和反馈

### 4. Excel / CSV 表格

适用：用户以前自己做过成长记录表、喂养表、睡眠表、身高体重表、健康记录表。

扫描内容：

- 工作表名称
- 表头字段
- 日期列
- 时间列
- 孩子称呼列
- 备注列
- 图片/附件路径列
- 与 child-growth-os 标准字段的映射关系

处理规则：

- 先生成字段映射建议，不直接导入。
- 识别每个 sheet 更像哪个目标表。
- 字段无法对应时，放入 `未映射字段`，不要丢弃。
- 如果表格里有照片路径，先进入照片资产库，再和目标记录关联。

确认后写入：

- 对应目标表，例如喂养、睡眠、尿片、健康、身体成长曲线
- `照片资产库`
- `同步日志` 或 `导入任务记录`

### 5. 飞书导出

适用：用户以前已经有飞书多维表格，或从旧版本 child-growth-os / QClaw 技能包导出数据。

扫描内容：

- base 或导出文件里的表名
- 字段名和字段类型
- 附件字段
- 关联字段
- 记录 ID
- 附件下载状态
- 旧表名与新表名映射

处理规则：

- 如果是飞书在线 base，优先原地升级，不导出再导入。
- 如果是飞书导出文件，先生成旧表到新表的映射清单。
- `宝宝档案` 兼容迁移为 `孩子档案`。
- 附件必须重新进入或映射到 `照片资产库`。
- 旧记录 ID 作为 `legacy_record_id` 保留。

确认后写入：

- 本地 JSONL
- 本地 Excel
- 或飞书原 base 的字段升级结果

### 6. 手机相册整理包

适用：iPhone/Android 相册导出、华为/小米/Google Photos/iCloud 下载、按相册或月份整理的压缩包。

扫描内容：

- 相册名
- 文件夹名
- 照片/视频 EXIF
- Live Photo 配对关系，如有
- 同一事件的连拍/重复照片
- 手机相册里的收藏、地点、人物信息，如导出包包含

处理规则：

- 相册名可以作为标签或专题名。
- 连拍照片应合并为一个候选事件，不要默认每张生成一篇日记。
- 视频和照片都进入照片资产库，媒体类型区分。
- 如果相册名是“生日”“医院”“幼儿园”等，应提高重要节点置信度。
- 必须生成本地照片故事填写页，让用户按照片补故事，而不是只给文件清单。

确认后写入：

- `照片资产库`
- `每日成长日记`
- `成长时间轴`
- `健康档案`

### 7. 其他育儿 App 导出数据

适用：喂养、睡眠、尿片、身高体重、疫苗、早教打卡等 App 导出的 CSV、Excel、JSON、HTML 或 PDF。

常见来源类型：

- 喂养记录 App
- 睡眠记录 App
- 生长曲线 App
- 宝宝相册 App
- 亲宝宝/宝宝树等导出包
- 疫苗或体检记录导出

扫描内容：

- 导出格式
- 时间范围
- 数据类型
- 字段单位
- 时区
- 图片/附件路径
- 备注文本
- 是否有统计汇总而非明细

处理规则：

- 先识别来源 App 和数据类型。
- 单位必须确认，例如奶量 ml/oz、体重 kg/g、身高 cm。
- 汇总数据和明细数据分开处理。
- 没有原始明细时，只能生成阶段摘要，不能伪造日级记录。
- PDF 或 HTML 报告可作为健康/成长附件进入照片资产库或文件资产。

确认后写入：

- `喂养记录`
- `睡眠记录`
- `尿片记录`
- `身体成长曲线`
- `健康档案`
- `照片资产库`
- `孩子当前状态`

## 置信度与确认规则

高置信度可建议批量确认，但仍不能跳过用户确认。

高置信度条件：

- 日期明确
- 来源明确
- 目标表明确
- 无重复
- 不涉及医疗判断
- AI 描述只是客观画面，不包含高风险推断

必须人工确认：

- 日期不确定
- 照片像医疗资料
- 涉及发热、用药、过敏、外伤
- 同一照片可能重复
- 不确定是不是用户孩子
- 需要判断是否“第一次”
- 需要合并多张照片为一个事件
- 其他 App 字段单位不明确

## 去重与合并

去重线索：

- 文件 hash
- 文件大小
- 图片尺寸
- EXIF 时间
- 感知哈希
- 文件名相似
- 同一微信消息 ID
- 同一飞书附件 ID

合并规则：

- 重复照片只保留一个正式 `asset_id`，其他来源写入 `duplicate_sources`。
- 连拍照片可以合并为一个事件，保留多张照片资产。
- 同一天多条短文本可合并为当天成长日记，但重要事件仍可单独进入成长时间轴。

## 导入完成报告

正式导入后，生成：

```text
imports/reports/{import-task-id}-done.md
```

报告应包含：

- 导入来源
- 扫描数量
- 跳过数量
- 正式导入数量
- 创建照片资产数量
- 创建日记数量
- 创建时间轴数量
- 创建健康记录数量
- 重复项数量
- 需要后续补充的项目
- 错误和失败文件清单

完成后给用户的口径：

```text
旧资料已经按你确认的清单导入完成。

这次共处理 {total} 项：
- 照片资产：{photo_count} 个
- 成长日记：{journal_count} 条
- 成长时间轴：{milestone_count} 条
- 健康档案：{health_count} 条
- 跳过/重复：{skipped_count} 项

还有 {needs_followup_count} 项日期或说明不完整，我已放到待补充清单里，之后你有空再补就行。
```

## 用户常用指令

```text
这是我以前整理的照片文件夹：D:\OldBabyPhotos。请只扫描，先给我待确认清单，不要直接导入。
```

```text
这是微信导出的聊天记录和图片文件夹：D:\WeChatExport。请帮我识别哪些可以导入孩子成长档案。
```

```text
这是以前喂养 App 导出的 CSV。请先分析字段，告诉我能映射到哪些表。
```

```text
这是我以前写的 Word 日记。请按日期拆成成长日记候选，先让我确认。
```

```text
这是亲宝宝/相册 App 导出的照片包。请识别拍摄日期和照片内容，生成待导入清单。
```
