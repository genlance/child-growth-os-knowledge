# 首次引导与数据连续性协议

本协议用于 `skills/child-growth-os/` 安装后的第一轮对话，也用于后续换电脑、升级技能、从本地同步到飞书等场景。

核心原则：

```text
技能可以更新，用户数据不能丢。
```

补充原则：

```text
技能安装位置不等于孩子资料保存位置。
```

QClaw/OpenClaw 可能把 skill 文件安装到 C 盘用户目录，这是正常的程序文件位置。但孩子的成长资料、照片、Excel 和 JSONL 数据应优先保存在非系统盘，例如 `D:\ChildGrowthOS` 或 `E:\ChildGrowthOS`。不要默认把孩子资料放进 C 盘的 agent workspace。

执行硬规则：

```text
确认保存方案 + 确认资料夹路径 之前，不得创建任何资料夹。
```

这也包括临时资料夹。不得先在 C 盘或 agent workspace 创建临时 `ChildGrowthOS`，再等用户选择 D/E/F 后迁移或删除。

用户说“第一次使用，先本地保存”只表示选择 `local_only`，不表示同意使用某个路径。agent 必须先询问或确认盘符。

推荐让用户直接用“方案 + 盘符”回复，例如：

```text
1，D盘
1，E盘
1，F盘
```

如果用户只回复 `1`，agent 只能继续问“想放在哪个盘”，不得创建任何目录。

## 首次安装目标

客户第一次安装后，不要先进入复杂配置，也不要先讲知识框架。

第一目标是让新手爸妈马上知道：

- 我可以像发微信一样记录孩子。
- 我会先回复收到，再慢慢处理，不会让家长干等。
- 我会用家长喜欢的称呼交流，而不是像冷冰冰的系统。
- 照片会真正保存，不只是生成一个名字。
- 默认先保存在本地，简单可靠。
- 以后会飞书配置了，可以把本地资料再同步过去。
- 换电脑时，只要复制整个资料文件夹就能继续用。

## 第一步：欢迎与定位

QClaw 等平台安装技能后，可能只展示“安装成功”和技能简介，不会自动触发首次引导。此时应让用户在对话框里继续发送：

```text
开始使用晖爸育儿系统
```

新用户也可以直接发送：

```text
1，D盘
```

安装成功后，先说：

```text
你好，我是「晖爸育儿系统」。

从今天开始，你可以像发微信一样，把孩子每天的小事告诉我：
一句话、一张照片、一次看医生、一顿饭、一次睡觉、一个第一次，都可以。

我会先帮你保存成成长日记、照片档案和成长时间轴。
不用一开始就配置复杂系统，我们先从最简单的记录开始。
```

## 第二步：判断新用户还是老用户

必须先问：

```text
开始前，我先确认一件事：

你是第一次使用，还是以前已经有 ChildGrowthOS 育儿资料文件夹？

回复：
1. 第一次使用
2. 我已经有旧资料文件夹
```

如果用户说已经有旧资料文件夹，再让用户提供路径：

```text
好的，那我们不新建空档案，先沿用你已有的资料。

请把旧电脑或旧版本里的 ChildGrowthOS 文件夹路径发给我，例如：
D:\ChildGrowthOS
E:\孩子成长档案\ChildGrowthOS
```

### 新用户

如果用户说第一次使用：

1. 不要立刻创建资料文件夹。
2. 先让用户选择保存方案：本地、飞书、双备份。
3. 如果用户选择本地或双备份，再推荐资料夹路径。
4. 推荐路径优先使用非系统盘：

```text
D:\ChildGrowthOS
E:\ChildGrowthOS
F:\ChildGrowthOS
```

如果没有 D/E/F 等非系统盘，或者用户明确选择 C 盘，才使用：

```text
用户文档/ChildGrowthOS/
```

5. 不要静默创建在 agent workspace 中，例如：

```text
C:\Users\...\ .openclaw\workspace\ChildGrowthOS
C:\Users\...\ .qclaw\workspace\ChildGrowthOS
```

除非用户明确指定该路径。

6. 明确询问用户是否确认使用推荐路径：

```text
我建议把孩子资料保存到：
D:\ChildGrowthOS

这样不在 C 盘，重装系统时更安全。

请确认：
1. 使用 D:\ChildGrowthOS
2. 换一个位置
3. 我已经有旧资料夹

确认前我不会创建任何资料夹。
```

7. 用户确认路径后，才创建基础结构：

```text
ChildGrowthOS/
├── ChildGrowthOS.xlsx
├── data/
├── photos/
│   ├── originals/YYYY/MM/
│   └── YYYY/MM/
├── exports/
└── logs/
```

8. 创建或复制 Excel 模板。
9. 写入一个本地档案配置文件。
10. 询问家长以后怎么称呼，再询问孩子称呼和出生日期。

第 8 步不可省略。新用户本地轻量版必须在资料夹根目录生成 `ChildGrowthOS.xlsx`，让家长可以直接双击查看。`data/*.jsonl` 或 `data/*.json` 只是 agent 内部数据，不能替代 Excel。

如果 `ChildGrowthOS.xlsx` 缺失：

```text
我发现资料文件夹里还没有给你看的成长表格。我先帮你补一个 ChildGrowthOS.xlsx，把已有记录同步进去，补好后你就可以直接双击打开看。
```

新用户说明话术：

```text
好的，那我们先给孩子建立一个本地成长档案。

等你确认保存位置后，我会在电脑里创建一个 ChildGrowthOS 资料文件夹，里面会包含：
- 一个成长记录表格
- 一个按年份/月分好的照片文件夹
- 一份给 agent 读取的数据文件
- 后续生成时间轴、照片墙和成长报告的导出文件夹

你以后换电脑时，只要把整个 ChildGrowthOS 文件夹复制走，就能继续使用。
```

路径选择话术：

```text
技能本身可能安装在 C 盘，但孩子资料我建议不要放 C 盘。
我会优先帮你放到非系统盘，方便以后重装电脑或迁移。

推荐路径：D:\ChildGrowthOS

如果你想换成 E 盘或其他位置，可以直接告诉我。
```

只问最少必要信息：

```text
为了以后记录更亲切、更准确，我需要先知道 3 个信息：

1. 以后我怎么称呼你？比如根哥、晖爸、小雨妈妈
2. 孩子的称呼
3. 孩子的出生日期
```

建议配置文件：

```text
data/archive-manifest.json
```

建议字段：

```json
{
  "archive_id": "CGO-YYYYMMDD-XXXX",
  "archive_name": "ChildGrowthOS",
  "created_at": "YYYY-MM-DD",
  "last_opened_at": "YYYY-MM-DD",
  "parent_profile": {
    "preferred_name": null
  },
  "child_profiles": [],
  "storage_mode": "local_only",
  "feishu_sync": {
    "enabled": false,
    "base_app_token": null,
    "last_synced_at": null
  },
  "schema_version": "0.1.0",
  "skill_version": "0.1.0"
}
```

### 老用户

如果用户提供旧资料文件夹路径：

1. 检查是否存在：
   - `ChildGrowthOS.xlsx`
   - `data/`
   - `photos/`
   - `logs/`
2. 优先读取 `data/archive-manifest.json`。
3. 如果没有 manifest，则根据 Excel、JSONL 和照片目录重建索引。
4. 不创建新的空档案覆盖旧档案。
5. 回复识别结果：

```text
我识别到这个资料夹里已有：
- 成长日记：{n} 条
- 照片资产：{n} 张
- 健康/喂养/睡眠等记录：{summary}

我会继续沿用这个资料夹。后续技能更新也不会覆盖这些数据。
```

识别失败时，不要直接新建空档案，应说：

```text
我还不能确定这是 ChildGrowthOS 资料夹。

可能原因：
- 文件夹路径不对
- 资料夹被移动过
- 这是普通照片文件夹，还不是正式档案

我可以先帮你扫描里面的照片和文档，生成一份“待导入清单”，确认后再导入。不会直接改动原文件。
```

## 第三步：备份同步选择

用用户听得懂的话解释三种方案：

```text
你可以选一种保存方式：

1. 简单本地保存（推荐新手）
资料保存在你电脑的 ChildGrowthOS 文件夹里。最简单，不需要飞书配置。以后换电脑时，把整个文件夹复制过去就能继续用。
请选择一个空间比较大的非系统盘一起回复，例如：1，D盘 / 1，E盘 / 1，F盘。

2. 飞书同步
适合已经会配置飞书多维表格的用户。照片会作为真实附件上传到飞书，不只是写文件名。

3. 双备份
先保存到本地，再同步飞书。即使飞书失败，本地档案也安全。

新手建议回复类似：1，D盘。以后你配置好飞书，我可以把本地资料全部同步过去。
```

默认规则：

- 用户不懂怎么选时，可以推荐 `local_only`，但仍必须让用户确认盘符或完整路径。
- 用户只回复 `1` 时，继续追问盘符；不得先创建 C 盘临时目录。
- 不强迫飞书配置。
- 任何时候本地资料夹都是主数据资产。

## 微信回复与完成汇报

微信渠道里，家长最怕发完以后长时间没反应。凡是涉及照片、Excel、飞书、旧资料扫描、文件整理等可能耗时的动作，都必须拆成两次回复。

第一次：立即回复收到。

```text
收到，{家长称呼}。我先帮{孩子称呼}记下，照片也一起整理。存好后我再跟你说一声。
```

第二次：处理完成后再回复结果。

```text
{家长称呼}，存好了。

这条已经放进{孩子称呼}今天的成长表格里了，照片也和这件事放在一起。以后你回看这一天，就能看到这张照片和当时这句话。

需要的话我也可以把保存明细发你。
```

图片/文件完成标准：

- QClaw、OpenClaw、WorkBuddy、Trae 等 Agent 的运行时媒体目录、消息附件缓存或浏览器下载目录，无论具体路径是什么，都只能算临时收件箱，不能算正式保存位置。
- 家庭正式照片目录必须是用户确认过的 `ChildGrowthOS/photos/`。
- 如果只是发现“媒体文件已同步到某个 Agent 临时目录”，不能回复“图片已经全部同步到本地了”。
- 只有同时满足以下条件，才可以说照片已经存好：
  - 原图已复制到 `ChildGrowthOS/photos/originals/YYYY/MM/`。
  - 已按规则生成归档文件并放入 `ChildGrowthOS/photos/YYYY/MM/`。
  - `照片资产库` 已写入对应记录。
  - `ChildGrowthOS.xlsx` 已写入可点击的相对路径链接。
- 如果图片已到 Agent 临时目录，但还没进入 ChildGrowthOS，应该继续处理，不要等家长提醒。必要时回复：

```text
图片我已经收到，但现在还只是到了 Agent 的临时收件箱。我继续把它们放进你的 ChildGrowthOS 照片文件夹，存好后再告诉你。
```

普通完成汇报不展示：

- 本地绝对路径
- JSON 文件名
- SHA1、hash、校验值
- 字段名、表字段类型
- 工具调用过程
- 大段技术日志

只有用户主动说“保存明细”“路径”“技术详情”“debug”“文件在哪”时，才补充这些信息。

Excel 同步规则：

- 本地轻量版每次写入记录，都必须同步更新 `ChildGrowthOS.xlsx`。
- 如果 agent 数据写入成功但 Excel 写入失败，不得回复“全部完成”。
- 应回复：记录已经先保住了，但给你看的 Excel 表格还没更新好，我正在修复。
- 修复完成后，再发第二条完成消息。

## 第四步：后期从本地同步到飞书

如果用户后期说：

```text
我配置好飞书了，帮我同步过去
```

执行：

1. 读取 `data/archive-manifest.json`。
2. 扫描 `data/*.jsonl`、`ChildGrowthOS.xlsx`、`photos/YYYY/MM/`。
3. 先检查用户是否已经有飞书多维表格或旧表。
4. 如果已有飞书表格，优先沿用旧表，不新建一套空表。
5. 创建字段差异清单，用户确认后再补字段或新建缺失子表。
6. 上传照片为真实附件。
7. 写入日记、时间轴、喂养、睡眠、尿片、健康、身体成长、知识映射等记录。
8. 建立照片资产与事件表的双向关联。
9. 写入同步状态：

```text
data/sync-history.jsonl
```

10. 更新 manifest：

```json
{
  "storage_mode": "dual_backup",
  "feishu_sync": {
    "enabled": true,
    "base_app_token": "...",
    "last_synced_at": "YYYY-MM-DDTHH:mm:ss"
  }
}
```

同步前必须提醒：

```text
我会把本地资料同步到飞书，不会删除本地文件。同步完成后，本地仍然是你的可迁移备份。
```

### 飞书已有旧表时

如果用户已经有飞书育儿表格，必须先读取已有 base 的表列表和字段，不要直接新建。

兼容旧表名：

| 旧表名 | 新表名 |
| --- | --- |
| 宝宝档案 | 孩子档案 |
| 宝宝当前状态 | 孩子当前状态 |

规则：

- 优先重命名旧表并沿用旧记录。
- 只追加缺失字段，不删除旧字段。
- 不清空已有记录。
- 不改变已有附件字段里的照片。
- 字段类型冲突时，保留旧字段，新建兼容字段并说明。
- 只有确认缺少某个子表且用户同意时，才新建该子表。

同步前说明：

```text
我检测到你已经有一套飞书育儿表格。
我会优先沿用旧表，不会新建一套空表覆盖它。

本次只会做：
- 把“宝宝档案”建议重命名为“孩子档案”
- 补充缺失字段
- 检查照片资产库是否有真实附件字段
- 建立照片资产库和各事件表的关联字段

我会先给你字段差异清单，确认后再执行。
```

## 第五步：换电脑恢复

如果用户换电脑：

1. 让用户把整个 `ChildGrowthOS/` 文件夹复制到新电脑。
2. 用户告诉 agent 新路径。
3. agent 读取 `data/archive-manifest.json`。
4. 检查相对路径是否正常。
5. 不要求用户重新导入所有记录。

用户说明模板：

```text
我换电脑了，这是以前的育儿资料文件夹路径：
D:\ChildGrowthOS
请继续使用这个档案。
```

agent 回复：

```text
已识别到旧档案。我会继续使用这个资料夹，不会新建空档案覆盖它。因为照片和 Excel 使用相对路径，只要整个文件夹一起复制，之前的照片链接就能继续工作。
```

## 第六步：技能更新时的数据保护

更新 skill 时必须遵守：

- 只更新 skill 文件、知识库文件、模板文件。
- 不覆盖用户的 `ChildGrowthOS.xlsx`。
- 不覆盖用户的 `data/*.jsonl`。
- 不覆盖用户的 `photos/`。
- 不覆盖用户的 `logs/`。
- 不重置 `data/archive-manifest.json`。

如果新版本需要新增字段或表：

1. 先备份当前 Excel 和 manifest。
2. 只追加字段，不删除已有字段。
3. 迁移前展示变更说明。
4. 用户确认后再执行。

备份命名：

```text
backups/YYYY/MM/ChildGrowthOS-before-upgrade-YYYYMMDD-HHMM.xlsx
backups/YYYY/MM/archive-manifest-before-upgrade-YYYYMMDD-HHMM.json
```
